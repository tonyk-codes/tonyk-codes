#### AI News Dashboard — Supply Chain Intelligence (International Edition)

**Repository:** [ai-news-dashboard-demo](https://github.com/tonyk-codes/ai-news-dashboard-demo)

A fully automated supply-chain intelligence platform tracking global trade, customs, logistics, and export-control developments. The system ingests real articles from Google News RSS and a curated set of reputable regional outlets, classifies and translates them with GPT via OpenRouter, stores them in a monthly shard format, and publishes a daily risk-ranked briefing — entirely through GitHub Actions with no manual intervention.

**Architecture**

```
Google News RSS + Curated Outlets
          |
          v
  scrape_candidates()         <- keyword pre-filter, dedup against known URLs
          |
          v
  analyze_with_gpt()          <- OpenRouter (GPT) classify / translate / summarise
          |
          v
  normalize_article()         <- canonical article schema v3
          |
          v
  data/news/YYYY/MM.json      <- monthly shard storage
          |
     _____|______________________
    |            |               |
    v            v               v
build_runtime  score_risk_matrix  pick_top20
    |            |               |
    v            v               v
articles.json  risk-matrix.json  top20.json
          |
          v
    index.html (static GitHub Pages dashboard)
```

**Top-20 Scoring Algorithm**

The daily briefing is not simply the most recent items. Each article is scored across four dimensions and ranked strictly by risk level first:

| Factor | Weight |
|---|---|
| Risk level (1 low — 4 critical) | Primary sort key; dominates all other factors |
| Recency | 100 points today, minus 30 per day |
| Section weight | Hubs / Carriers / Customs = 40 · Business banner = 35 · Customs banner = 30 |
| Risk-matrix cell boost | +15 if the article matches a cell rated High or above |

Priority tiers are assigned at output: ranks 1–3 as critical, 4–10 as important, 11–20 as normal. The frontend consumes `top20.json` directly for the daily briefing tab.

**Automation**

The GitHub Actions pipeline runs in a matrix of parallel regional jobs at 22:00 UTC (06:00 HKT) every day. Each job scrapes and classifies a single region, emits a JSON artifact, and a downstream merge job consolidates shards, rebuilds the runtime index, and re-scores the risk matrix via LLM.

**Entity Coverage**

The platform tracks structured entities across four dimensions: port and airport hubs, shipping carriers and airlines, customs agencies, and countries. Each entity has a curated profile card in `data/profiles.json` generated by `build_profiles.py`.

**Stack:** Python · OpenRouter GPT · GitHub Actions (matrix workflow) · Vanilla JS · JSON shard storage

#### Executive Mindset AI

**Repository:** [executive_mindset_ai](https://github.com/tonyk-codes/executive_mindset_ai)

An interactive AI coaching platform built for Huawei executive training. Delivers structured mindset development sessions through a multi-tab Gradio interface. The system loads a LoRA fine-tuned causal language model with 4-bit quantization (BitsAndBytesConfig) for efficient GPU inference on Nvidia A100 hardware, and pairs text responses with high-quality speech synthesis from fal.ai. Deployed as a persistent Hugging Face Space.

**Technical Detail**

- Model loading uses `PeftModel` with `PeftConfig` for LoRA adapter composition on top of a base causal LM loaded via `AutoModelForCausalLM` and `AutoTokenizer`
- 4-bit quantization via `BitsAndBytesConfig` reduces VRAM footprint while preserving generation quality on A100
- Text-to-speech is handled asynchronously through `fal_client`, enabling natural audio responses to coaching prompts
- The Gradio UI is structured with tabbed sections, supporting multi-turn dialogue with session state

**Stack:** Python · Gradio · Hugging Face Spaces (A100) · PEFT / LoRA · Transformers · fal.ai TTS · BitsAndBytes 4-bit quantization

#### AI Personalized Marketing Video Agent

**Repository:** [AIPersonalizedMarketingAgent](https://github.com/tonyk-codes/AIPersonalizedMarketingAgent)

A three-stage generative AI pipeline that produces fully personalized marketing video advertisements from a customer profile and a product selection. Each stage feeds directly into the next, with no human authoring between input and final video output.

**Pipeline**

```
Customer Profile Input
  name · age · gender · nationality · location
Product Selection (6 Nike shoe categories)
          |
          v
Stage 1 — Slogan + Product Description
  Model: Qwen2.5-VL-7B-Instruct (HKUST Nike fine-tune, dedicated HF endpoint)
  Input: customer profile + product image (vision)
  Output: personalized slogan ending with customer name + 2-sentence description
          |
          v
Stage 2 — Cinematic Video Script
  Model: GLM-4.7-Flash via Novita
  Input: customer profile + slogan + product description
  Output: structured 8-section production prompt
          [Subject] [Scene] [Motion] [Camera] [Lighting]
          [Personalization] [End Frame + On-Screen Text] [Style]
          |
          v
Stage 3 — Video Generation
  Model: fal-ai/sora-2 image-to-video/pro
  Input: product image + cinematic script
  Output: short advertisement video rendered to screen
```

**Personalization Depth**

The slogan model is constrained to a precise format: five words maximum before the comma, ending with the customer's first name, zero punctuation except that single comma. The description model generates exactly two sentences tailored to the customer's age group energy, gender presentation, cultural background, and city environment. The cinematography prompt instructs the video model to render a hero who plausibly resembles the customer's demographic and to maintain shoe visibility throughout all shot types.

**Stack:** Python · Streamlit · Qwen2.5-VL-7B (vision-language, HKUST fine-tune) · GLM-4.7-Flash · fal-ai/sora-2 · Hugging Face Inference API

A machine-learning-driven financial analysis platform covering 51 symbols across US equities, ETFs, leveraged products, cryptocurrencies, and Hong Kong-listed stocks. Four independent strategy modules run against the full watchlist and publish results to a static GitHub Pages dashboard.

**Watchlist Composition**

| Category | Examples |

| ETFs | QQQ, VOO, VTI, VUG, VT, SCHD |

**Signal Strategies**

| Strategy | Method | Output |
|---|---|---|
| MA Golden Cross | 50-day vs. 200-day SMA crossover on 1-year daily history | Signal: Golden Cross / Death Cross / Bullish / Bearish + 60-day SMA chart history |
| News Sentiment | FinBERT (`ProsusAI/finbert`) via HF Inference API on last 20 headlines; lexicon fallback (40 positive / 40 negative financial terms) | Per-headline label + score; aggregate average |
| FinRL-Inspired Composite | 6-month daily data: momentum (5d, 20d), RSI-14, MACD (12/26/9 EMA), Bollinger Bands (20-day, 2σ), annualised volatility, Sharpe ratio, linear trend slope | Composite score with reason strings; Buy / Hold / Sell signal |
| Correlation Analysis | 3-month return correlation matrix across all tracked instruments | Heatmap for portfolio diversification assessment |

**FinRL Composite Scoring (selected rules)**

```
momentum_20d > 5%      → +2   |  momentum_20d < -5%   → -2
RSI < 30               → +2   |  RSI > 70              → -2
MACD histogram > 0     → +1   |  MACD histogram < 0   → -1
BB position < 0.2      → +1   |  BB position > 0.8    → -1
Sharpe > 1.5           → +1   |  Sharpe < -0.5        → -1
```

**Rule-Based Buy/Sell Framework (Quant Spec, GitHub-Safe)**

Notation: `P_t` price, `MA20_t` and `MA50_t` moving averages, `RSI14_t` RSI(14), `r_5d_t_QQQ` 5-day QQQ return, `u_t` unrealized PnL, `P_peak_t` running peak price, `H_52w_t` 52-week high, `Nneg_t` negative fundamental-news flag (1 if true, else 0).

| Signal | Formal Definition |
|---|---|
| BUY_TL(t) | `1{ P_t > MA50_t and MA20_t >= MA50_t and Delta(MA50_t) > 0 and 0.92*MA20_t <= P_t <= 1.02*MA20_t and 35 < RSI14_t < 65 and r_5d_t_QQQ > -0.05 }` |
| BUY_N(t) | `1{ P_t > MA20_t and P_t > MA50_t and 0.93*MA20_t <= P_t <= 1.00*MA20_t and 40 <= RSI14_t <= 60 and r_5d_t_QQQ > 0 }` |
| SELL_TL(t) | `1{ (u_t >= 0.25 and RSI14_t >= 75) or (P_t < 0.97*MA20_t) or (P_t < 0.82*P_peak_t) or (Nneg_t = 1) }` |
| SELL_N(t) | `1{ (u_t >= 0.12 and RSI14_t > 65) or (P_t < MA50_t) or (P_t < 0.90*P_peak_t) }` |
| TL(t) | `1{ (R_60d_t >= 0.40 or R_120d_t >= 0.80) and P_t >= 0.80*H_52w_t }` |
| N(t) | `1 - TL(t)` |

Take-profit execution detail: for the first clause in `SELL_TL(t)`, reduce position by 25-33%.

**Stack:** Python · NumPy · Pandas · yfinance · FinBERT (HuggingFace) · GitHub Actions · GitHub Pages · Vanilla JS

#### VesselCheck

**Repository:** [vesselcheck](https://github.com/tonyk-codes/vesselcheck)  
**Live:** [tonyk-codes.github.io/vesselcheck](https://tonyk-codes.github.io/vesselcheck)

A single-page web application for querying vessel arrival and departure movements in Hong Kong waters, built on Marine Department and data.gov.hk open data feeds. Designed for reliability-first operation in a constrained CORS environment.

**Query Modes**

| Mode | Data Source | Coverage |
|---|---|---|
| Last 36 Hours | Live XML feeds from Hong Kong Marine Department | Real-time arrivals and departures |
| Historical Range | data.gov.hk Historical Archive API (snapshot-based) | Up to 20 days per query |

**Reliability Engineering**

The application handles multiple failure modes inherent to public open-data endpoints: CORS restrictions are resolved through a fallback chain to public CORS proxies; the historical archive sampler requests snapshots at 30-minute intervals to ensure record completeness; duplicate records from overlapping fetches are deduplicated by identity; and all network requests use automatic retry with incremental backoff before surfacing an error.

**Output**

Results include summary statistics (total movements / arrival count / departure count), a sortable table with arrival/departure badges and publisher information, and highlighted partial matches when a vessel name filter is active.

**Stack:** Vanilla JS · HTML/CSS · HK Marine Department Open Data XML · data.gov.hk Historical Archive API

#### ZenPath — A Mindful Puzzle Game

**Repository:** [ZenPath](https://github.com/tonyk-codes/ZenPath)

A sliding-block word puzzle game for iOS and Android, built with Flutter and the Flame game engine. The objective on each stage is to slide all word-bearing blocks out through the exit gate at the top of the board, then arrange the collected words in the correct order to complete a mindful phrase. The game features progressive difficulty, a retro pixel-art visual design, ambient audio, and full trilingual support.

**Core Game Mechanics**

The board is a 5×5 grid with exactly three empty spaces. Word blocks carry individual words or characters from the target phrase. The player slides rows and columns to route each word block to the exit gate at column 2 of the top row. Once all word blocks have exited, they appear in a parking area from which the player arranges them in sequence. A countdown timer creates urgency, decreasing by one second per stage from a starting value of 150 seconds, with a minimum floor of 30 seconds.

**Function Block System**

The game introduces special blocks on a stage-gated schedule, increasing tactical complexity over time:

| Block Type | Introduced | Behaviour |
|---|---|---|
| Time Bonus (+5 / +10) | Stage 1+ | Exits the gate and adds seconds to the timer |
| Star Block | Stage 5+ | Tap to extract any target word block instantly |
| Hard Rock | Stage 10+ | Immovable obstacle; cannot be slid or exited |
| Sticky Box | Stage 20+ | Chain-pushes adjacent blocks when moved |
| Time Bomb | Stage 30+ | 10-second internal countdown; explodes into a Hard Rock |

**Visual & Audio Design**

The visual identity uses a warm pixel-art sunset palette — layered gradients from deep purple sky (`#3C2248`) through salmon and peach to sand tones — rendered with a wooden-frame mosaic border around the game board. Block animations use a spring physics model (damping 0.78, stiffness 300) with squash-and-stretch on movement and idle jiggle cycles for living character. Stage completion triggers a full-screen confetti burst with eight vibrant pixel colors. Audio is managed through the Flame audio subsystem with separate toggles for background music and sound effects.

**Internationalisation**

The game is fully localised in English (DotGothic16 retro pixel font), Traditional Chinese (NotoSansTC), and Simplified Chinese (NotoSansSC). The phrase pool is language-specific, and the word extraction and arrangement logic handles both space-delimited (English) and character-level (CJK) tokenisation correctly.

**Monetisation & Distribution**

Monetisation uses Google AdMob for banner ads with a non-consumable in-app purchase (`zenpath_remove_ads_forever`) for permanent ad removal, implemented via the `in_app_purchase` package supporting both StoreKit 2 (iOS) and Google Play Billing. Full compliance documentation for both the Apple App Store and Google Play Store review processes is included in the repository.

**Stack:** Flutter · Dart · Flame Engine 1.35 · flame_audio · Google AdMob · in_app_purchase · SharedPreferences · DotGothic16 · NotoSansSC · NotoSansTC
